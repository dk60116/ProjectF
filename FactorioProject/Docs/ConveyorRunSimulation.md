# 직선 컨베이어 묶음 시뮬레이션 — 1단계

## 적용 범위

- 동일 속도·동일 간격의 직선 벨트 2개 이상, 가상 아이템 모드에서 자동 적용한다.
- 같은 아이템 종류와 같은 이동/픽업/홀드 상태가 연속되면 하나의 run으로 저장한다.
- 코너·2층·속도가 다른 구간·순환 경로(순환 경로로 이어지는 구간 포함)는 기존 시뮬레이션을 사용한다.
- 개별 PortableObject가 필요하거나 코너 연속 이동 상태가 들어오면 현재 아이템과 이동 시각을 슬롯 저장소로 복원한다.

## 데이터 소유권

`ConveyorRunStore`가 첫 슬롯, 개수, 아이템 ID, 공통 이동 시작 시각/시간,
픽업 게이트와 홀드 상태를 소유한다. 끝 슬롯은 첫 슬롯과 개수로 계산한다.
경로는 최초 위치와 슬롯 간 벡터를 캐시한다. 슬롯 번호는 이동 방향으로 증가한다.

`BlockRuntimeSimulationState`의 버퍼는 연결 중 `ConveyorRunBinding`을 통해
묶음을 조회한다. 기존 로컬 아이템 ID와 이동 상태는 연결 시 지운다.
중간 삭제/삽입은 해당 묶음을 분할하고, 같은 상태가 인접하면 병합한다.
저장·로봇팔·플레이어 조회는 이 뷰를 사용하며 저장 포맷은 바꾸지 않았다.

## 이동 및 경계

일반적인 내부 이동은 슬롯별 Clear/Set 없이 묶음 첫 슬롯과 공통 이동 상태를 갱신한다.
이동 도착 시간 또는 외부 변경이 있을 때만 묶음을 처리한다. 경계 출력만 기존
이송 계획기를 사용한다. 기존 계획기가 압축 구간 내부를 개별 아이템으로 밀거나
끌어가지 않도록 차단한다. 실제로 빈 슬롯만 기존 대기자에게 알린다.
구조 변경/해제 시에는 모든 연결의 스냅샷을 먼저 복원한 뒤 기존 완료 예약을 복구한다.

## 아직 바뀌지 않은 비용

- 이것은 전체 GPU run 렌더러 전환 완료가 아니다. 기존 인스턴스 렌더러를 유지한다.
- 렌더 캐시는 이동 이벤트마다 블록별로 갱신하며, GPU에도 여전히 개별 인스턴스 데이터가 전달된다.
- 따라서 이동 계산은 묶음 수 기준으로 줄지만, 전체 CPU 비용이 묶음 수에만 비례하지는 않는다.
- 상태 또는 종류가 모두 다르면 run 수가 아이템 수와 같아질 수 있다.
- 한 run은 한 프레임에 최대 한 슬롯을 진행한다. 일반 완료 시 잔여 시간은 유지하지만,
  긴 프레임 정지 후의 다중 슬롯 따라잡기는 후속 검증/확장 대상이다.
- 셰이더에 경로·묶음 정보를 직접 전달하는 렌더러, 혼합 종류 시퀀스 압축,
  곡선/순환 경로의 묶음 이동은 다음 단계다.

## 검증 진입점

Unity 메뉴: `Tools/ProjectF/Diagnostics/Validate Conveyor Run Store`

명시적으로 선택할 때만 실행한다. 런타임 자동 실행이나 씬 수정은 없다.
`ConveyorRunStoreHarness.Run()`은 다음을 검사한다.

- 10,000개 연속 아이템 이동이 run 하나만 방문하는지
- 시간 0에서 시작한 이동과 정확한 도착 시각
- 중간 삭제, 다른 종류 삽입, 양쪽 재병합, 정체 후 해제
- 슬롯 어댑터 연결/해제 시 ID 및 이동 좌표/시각 보존
- 픽업 게이트/홀드/종류를 바꾸는 고정 시드 2,000단계의 슬롯 참조 모델 비교

프로파일러 카운터: `ConveyorSimulation.RunPaths`, `ConveyorSimulation.Runs`.
기존 벨트 진단은 동일 슬롯 뷰로 전체 아이템 수와 저장 중복 여부를 확인한다.

작성 시 프로그램 실행 금지 지침에 따라 Unity 실행, 컴파일, 하네스 실행 및
실제 로봇팔/저장/청크 경계 통합 검증은 수행하지 않았다. 성능 향상 수치를 측정한 상태가 아니다.
