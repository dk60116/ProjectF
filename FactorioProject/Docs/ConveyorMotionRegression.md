# 벨트 이동 완료 회귀 검증

## 중간 수거 후 순간이동·끊김

실물 아이템은 블록의 누적 tick 시간으로 이동하고 가상 아이템은 출발 시각으로
이동했다. 특히 새로 만든 실물 이동에도 과거 tick 간격을 즉시 적용하거나,
같은 프레임에 다른 블록으로 옮긴 아이템을 그 블록의 누적 시간으로 다시
진행시키는 경로가 있었다. 정체 해제 후 다른 아이템과 이동량이 달라질 수 있었다.

- 실물/가상 아이템 모두 `ConveyorMotionTiming`의 구간 출발 시각·이동 시간으로 진행률을 구한다.
  같은 시각에 다시 조회해도 이동량이 누적되지 않으며, 렌더링과 이동 가능 판정도 같은 값을 사용한다.
- 도착 후 새 계획은 현재 시각에 시작한다. 블록의 대기 시간이나 이전 구간의
  늦은 처리 시간을 새 계획의 아이템 하나에 추가하지 않는다.
- 직선/코너 및 가상 렌더링 여부에 따라 중복되어 있던 실물 이동 갱신과
  `AdvanceStarted...` 선행 이동, 사용처가 없던 carry 진입점을 제거했다.
- 수거 미리보기의 실물화는 가상 이동의 출발 위치, 경유점, 코너 경로와 시각을 이전한 뒤
  가상 이동 소유권을 해제한다. 이동 중 아이템을 슬롯 도착 상태로 바꾸지 않는다.
- 실물 아이템의 반복 갱신 요청은 곧바로 개별 큐에 넣어 매번 묶음 큐를 거쳐 되돌아오지 않는다.
- 저장 형식은 그대로이며, 저장 시 현재 진행률을 기록하고 복원 시 그 진행률에서 시계를 시작한다.

Unity 메뉴 `Tools/ProjectF/Diagnostics/Validate Conveyor Motion Timing`에
긴 정지 뒤 재출발, 같은 시각 중복 조회, 늦은 도착, 진행률 복원, 시간 0,
직선/코너 미리보기 전환 시 경로·시각·단일 소유권 보존 검증을 추가했다.
이 하네스는 비활성 preview scene의 별도 인스턴스를 사용하며 자동 실행되지 않는다.
이번 작업에서는 실행하지 않았다.

실제 게임 회귀 시나리오(미실행): 벨트를 충분히 정체시킨 뒤 중간 아이템 하나만 꺼내고,
바로 뒤 및 두 번째 뒤 아이템이 현재 위치에서 정상 속도로 출발하는지 확인한다.
직선/코너, 로봇팔 투입과 손 수거 미리보기, 실물/가상 혼합을 각각 포함한다.
길게 지연된 프레임에서 예약된 다음 슬롯을 넘어 순간 진행하지 않는지도 확인한다.

## 앞이 빈 아이템과 실물 아이템이 섞인 직선 구간

직선 구간에 실물 `PortableObject`가 있으면 가상 아이템 묶음 처리에서
개별 처리로 전환한다. 이전 분기는 실물 아이템이 있는 블록만 개별 큐에
넣어, 같은 범위의 가상 아이템 블록을 처리하지 않았다. 뒤 실물 아이템이
도착하여 이동 계획으로 밀어 주기 전까지 앞의 가상 아이템이 멈출 수 있었다.

- 전환 시 해당 범위의 모든 아이템 보유/이동 필요 블록을 개별 큐에 넣는다.
- 묶음 시뮬레이션 캐시를 사용할 수 없는 경우도 같은 경로로 처리한다.
- `runtimeBlockersOnly` 분기와 중복 fallback 래퍼를 제거했다.
- 수거 미리보기의 실물화와 다시 가상화하는 동작은 연결 구조를 바꾸지 않으므로,
  이동 큐 전체를 지우던 구조 캐시 무효화 호출을 제거했다.
  미리보기 실물화 시에는 해당 블록의 활동 상태만 갱신한다.

회귀 시나리오(아직 실행하지 않음):

1. 같은 직선 처리 범위 안에 가상 아이템과 실물 아이템을 떨어뜨려 배치한다.
   가상 아이템 앞은 비워 둔다. 실물 아이템이 따라오기 전에 가상 아이템이 이동해야 한다.
2. 손 수거 미리보기로 실물 아이템을 만든 경우와 로봇팔 투입 직후에 각각 반복한다.
3. 구간 일부가 2층 벨트여서 묶음 캐시가 유효하지 않은 경우에도 개별 이동이 진행되어야 한다.
4. 다른 직선 구간에 이동 예약이 있는 동안 수거 미리보기를 켰다 끈다.
   다른 구간의 예약이 삭제되거나 이동이 멈추지 않아야 한다.
5. 개별 전환 범위 밖의 블록은 불필요하게 큐에 추가하지 않고,
   이미 직접 처리 중인 블록은 중복으로 예약하지 않아야 한다.

기존 Vacancy Wake 하네스는 빈 슬롯 예약을 검사한다. 위 혼합 아이템의
실제 이동과 미리보기 통합 시나리오는 별도 검증이 필요하며, 통과한 것으로 간주하지 않는다.

## 수거 후 바로 뒤 아이템이 계속 멈추는 문제

증상: 아이템을 빼내도 뒤 아이템이 움직이지 않고, 추가 투입이나 벨트 변경을 해야 재개한다.

- 이동 가능 여부만 조사하고 수면에 들어간 슬롯은 대기자 목록에 없을 수 있다.
  빈 슬롯 알림은 이제 실제 직전 슬롯도 조회하고, 해당 아이템의 수면·이동 지연·실패 캐시를 해제한다.
- 일반 이동 요청은 직선 구간의 재시도 지연에 흡수될 수 있다. 빈 슬롯으로 인한 재개 요청은
  이 지연을 취소한 뒤 즉시 큐에 넣고, 기존 재시도 범위도 함께 보존한다.
- 플레이어 손/가방 수거와 로봇팔 수거는 같은 제거 처리 함수를 사용한다.
  이미 이번 프레임에 처리한 직선 구간은 기존 다음 프레임 큐로 넘긴다.

Unity 메뉴 `Tools/ProjectF/Diagnostics/Validate Conveyor Vacancy Wake`에
예약 처리 회귀 하네스를 추가했다. 비활성 preview scene의 별도 인스턴스로
일반 요청이 지연되는 조건, 지연 취소, 대기 범위 보존, 중복 요청 병합,
다음 프레임 요청 보존을 검사한다. 자동 실행되지 않으며 이번 작업에서는 실행하지 않았다.

실제 게임에서는 출구가 막힌 벨트의 중간/맨 앞 아이템을 하나 수거하고,
새 아이템을 투입하지 않은 채 바로 뒤 아이템이 다음 시뮬레이션 처리에서
빈 슬롯으로 이동하는지 확인한다. 같은 블록 내부와 블록 경계, 코너, 2층 벨트에서
반복하고 손/가방 수거 및 로봇팔 수거를 각각 확인한다. 이 통합 검증은 아직 하지 않았다.

## 수정 대상

`Block.CompleteDueVirtualConveyorDataMotions`의 가상 아이템 완료 처리.
기존에는 다음 이동 계획 전체를 현재 시각에 적용한 뒤, 완료 처리 대상
아이템 하나만 지연 시간만큼 추가 이동시켰다. 이 계획에는 앞 아이템을
미는 동작과 뒤 아이템을 당기는 동작도 포함되어 있어 간격이 달라졌다.
지연 시간이 다음 구간 길이 이상이면 대상 아이템은 그 구간을 즉시
완료하고, 같은 프레임 이동 제한 때문에 다시 멈출 수도 있었다.

이제 완료 시 다음 이동을 즉시 시도하되, 계획에 포함된 모든 아이템은
현재 시각에서 출발한다. 도착 시각과 처리 시각이 정확히 같아도 동일하다.
시작 시각 0 또는 음수는 유효한 값이며, 타이밍 초기화 여부는 duration으로 판단한다.

## 실행 시 확인할 시나리오

1. 직선 벨트에 아이템 하나만 투입한다. 후속 투입 없이 끝까지 진행하는지 확인한다.
2. 간격 0.5, 속도 1인 직선에서 인접 아이템 두 개의 도착 처리를
   0.25초 늦춘다. 다음 이동 직후에도 간격이 0.5인지 확인한다.
   기존 경로는 완료 대상 하나에 0.25만큼 추가 이동을 적용할 수 있었다.
3. 같은 조건에서 지연을 0.5초 이상으로 늘린다. 대상 아이템만 앞 아이템의
   출발 위치까지 즉시 진행하거나 중간에 남는 현상이 없는지 확인한다.
4. 정확한 도착 시각에 처리한다. 다음 슬롯이 비어 있으면 바로 새 이동이 활성화되어야 한다.
5. 출구를 막았다가 비운다. 정체 중 아이템 수가 유지되고 해제 후 다시 이동해야 한다.
6. 코너 진입·이탈, 로봇팔 투입, 저장 후 복원을 거쳐 같은 항목을 확인한다.
7. 시작 시각 0, duration 0.5인 이동은 시각 0.25에서 진행률 0.5,
   완료 시각 0.5로 평가되어야 한다. 시작 시각 -0.25도 재초기화하지 않아야 한다.

## 검증 상태와 제한

코드와 호출부를 정적으로 검토했다. 프로그램 실행 금지 지침에 따라
Unity 실행, 컴파일 및 위 시나리오의 실제 실행은 하지 않았다.
예약 완료 경로는 늦어진 프레임의 잔여 시간을 다음 구간에 소급 적용하지 않는다.
따라서 낮은 프레임률에서는 실효 이동 속도가 낮아질 수 있다.
지연 보정 재도입 시에는 이동 계획 전체와 앞쪽 점유 상태를 함께 계산해야 한다.
