# Tick / GameObject 분리 — 3·4단계 진행 기록

작성일: 2026-09-14

## 현재 상태

**3·4단계의 일부 실행 코어와 표현 경계를 구현했어. 기획의 두 단계 전체 완료는 아니야.** 이전 1·2단계에서 남아 있는 공통 IO 계약·Block 없는 연결 복원도 아직 필요해. 이전 가능한 계산부터 실제 호출부에 연결했고, 사용하지 않는 별도 모의 월드를 게임에 추가하지 않았어.

SaveSlot2 원본, 바이너리 저장 포맷, 전체 청크 복원 범위는 바꾸지 않았어. 원거리 공정에 필요한 기존 로드를 유지했으며 근거리 View만 로드하는 5단계 최적화는 켜지 않았어. 이번 변경으로 수분 로딩이 해소됐거나 JobSystem 병렬화가 끝났다고 판단하면 안 돼.

## 3단계에서 적용한 부분

### 제작 진행 상태

- `Simulation/Core/ProductionProcess.cs`에 활성 배치·레시피 인덱스·완성품 ID/수량·남은 Tick·누적 사용 에너지·출력 대기를 모았어.
- InputOutputModule의 기존 7개 상태 필드는 이 값 타입의 접근자로 바꿨어. 기존 저장/복원 코드와 파생 설비가 같은 상태 원본을 읽고 써.
- 실제 Begin/Update/Clear가 코어를 호출해. 기존 에너지 어댑터가 수락한 양을 받아 진행하고, 완료 시 기존 가상 TryCompleteActiveCraft로 배출해. 출력 막힘 중에는 배치를 유지하고 에너지를 다시 차감하지 않아.
- 중복된 남은 에너지→Tick 계산과 개별 상태 초기화 코드를 제거했어. 정수 단위, 수면/깨움, 기존 출력 처리 순서는 유지해.
- 입력 재료 소비, 예약, 채굴 대상 조회, 인벤토리 소유권은 아직 InputOutputModule/InstallationObject/Block 쪽이야. 이 코어만으로 공장 전체가 무표시 실행되지는 않아.

### 전력 공급 계산

- `PowerSupplySnapshot`이 생산량·수요량·전원 유무와 비례 공급률/정수 에너지 지급 계산을 맡아.
- UtilityPole의 ElectricNetwork가 이 값을 소유하고, 일반 설비와 로봇팔의 실제 전력 요청을 같은 계산으로 연결했어.
- 중복 SupplyRatio 저장 필드와 공급률 계산을 제거했어. 스냅샷은 전력률 게시값이지 축전지나 예약 원장이 아니야. 같은 경과 시간의 요청을 중복 호출하면 안 돼.
- 전봇대 토폴로지와 발전기 검색·가동은 아직 Unity 어댑터에 있어. 전역 데이터 전력망 전체 이전은 남아 있어.

## 4단계에서 적용한 부분

### 월드 시간

- `WorldClock`이 날짜·주야·계절·배율·일시정지·식물 주간 경과 시간을 소유하고 실제 Tick을 받아.
- WorldTimeService는 달력 계산 대신 설정·저장 DTO·조명·기존 이벤트 API를 연결해. Tick 등록 대상도 MonoBehaviour가 아니라 WorldClock으로 바꿨어.
- WorldTimeService를 비활성화해도 시계는 유지하고 조명 반영만 멈춰. 명시적 SetPaused로 시간을 멈춰. **호스트 자체를 파괴하면 시계 등록을 해제해. 호스트 파괴까지 View 해제로 바꾼 것은 아니야.**
- 코어의 Capture/Restore는 주간 성장 시간과 시간 제어값도 보존해. 기존 디스크 WorldTimeSaveData는 날짜/시각만 저장하므로 로드 시 성장 시간 0, 배율 1, 일시정지 해제 규칙을 그대로 유지해. 완전한 파일 체크포인트 확대는 5단계 일이야.
- 주간 성장 누적은 기존처럼 Tick 시작 시 주간인지 판단해 실제 경과 시간을 더해. 계절 이벤트도 기존 최종 계절 변경 알림 의미를 유지해.

### 차량과 선로

- `VehicleMotionState`가 실제 Vehicle 가감속·역전 제동·속도 제한을 맡아. 중복 속도 계산을 제거했어.
- `RailPathSampling`이 실제 Railload의 누적 거리 이진 검색·위치·접선 계산을 맡아. struct 어댑터로 기존 점 목록을 전달하므로 샘플마다 복사/델리게이트/박싱을 만들지 않아.
- SteamTrain의 수동 운전 연료·물 차감을 LateUpdate에서 이동 처리 시점으로 옮겼어. 자동/수동이 같은 확정 경로를 사용해. 프레임별 대기 비용 필드 4개와 초기화 헬퍼 2개를 제거했어.
- 같은 렌더 프레임에 이동 처리가 두 번 수락되면 두 번의 비용을 반영해. 이전처럼 대기 비용이 덮어써지지 않아.
- 차량 위치/연결·노선·선로 점유·화물·정차는 여전히 기존 객체 기반이야. 수동 입력 시간도 아직 프레임 기반이고, SteamTrain LateUpdate에는 급수관 도킹 상태 변경이 남아 있어. 열차 전체 Tick 분리 완료는 아니야.

### 동물 AI 월드

- AnimalAIWorld를 MonoBehaviour에서 명시적인 IDisposable 서비스로 바꿨어. GameManager가 생성과 해제를 소유해.
- AnimalAIWorldView에 카메라 컬링·프레임 보간·표현 프레임 프로파일 완료를 옮겼어. AttachView/DetachView는 AI 등록이나 개체 목록을 바꾸지 않아.
- Dispose는 Tick 등록과 보유 참조를 정리해. View 재결합은 NeedsTick이나 개체 목록을 초기화하지 않아.
- 기존 AnimalAIWorld GUID를 참조하는 저장소의 scene/prefab/asset은 검색에서 발견되지 않았어.
- **개별 AnimalAIController는 아직 MonoBehaviour야.** 행동의 플레이어 거리 조회·상태/애니메이션 연결·지형 접근도 남아 있어. 이번 하네스는 월드 View 제거를 검증하지 모든 동물 GameObject 파괴를 검증하지 않아.

## 저장 및 데이터 영향

- ItemDefinition asset과 제작 트리 바이너리 원본은 변경하지 않았어.
- 제작의 Unity 직렬화 런타임 필드는 ProductionProcess 내부로 이동했어. 이전 필드의 에디터/핫 리로드 중간 상태 마이그레이션은 제공하지 않아. 디스크 저장은 기존 PersistentState 필드로 변환하므로 필드 배치와 단위를 유지해.
- scene/prefab/asset에서 활성 제작이나 양수 제작 진행 값을 가진 기존 직렬화 필드는 검색에서 발견되지 않았어.
- 새 코어는 엔진 참조 없는 기존 `ProjectF.Simulation.Core` asmdef 안에 있어. Job/Burst 병렬 실행으로 전환하지 않았어.

## 검증 결과

Unity 에디터·게임·PC UI는 실행하거나 조작하지 않았어. 소스 컴파일과 .NET 하네스만 실행했어.

| 검사 | 결과 |
| --- | --- |
| 순수 코어 .NET Standard 2.1 빌드 | 경고 0 / 오류 0 |
| 실제 게임 Assembly-CSharp 보충 참조 빌드 | 경고 113 / 오류 0 |
| SimulationCoreHarness | 244개 통과 |
| 실제 제작 Begin/Update/Complete/Clear 연결 검사 | 71개 통과 |
| AnimalAIOptimizationHarness | 68개 통과 |
| TrainAutoDriveHarness | 185,221개 통과 |
| BeltJobsHarness | 3,087개 통과 |
| RobotArmEcsHarness | 420개 통과 |
| PipeFlowHarness | 32개 통과 |
| SprinklerStorageHarness | 48개 통과 |
| SeedPlanterHarness | 18개 통과 |
| CheckBoundaries 소스 계약 | 코어 및 4개 월드 검사 통과 |

제작 연결 검사는 실제 상태 접근자와 메서드를 추출해 코어와 함께 실행하고, 에너지/출력 IO는 테스트 대역을 써. 정전·출력 막힘·중복 소비 방지·상태 재설정·중간 상태 복원을 검사했지만 실제 채굴→생산→보관 공정이나 파일 저장 왕복 검사는 아니야.

동물 검사는 실제 월드·새 View·독립 스케줄러와 Unity API 대역을 함께 실행해. View 해제 전후 Tick/행동 유지, 재결합, 소유자 해제를 확인했지만 실제 Unity 생명주기와 렌더링 검증을 대신하지 않아.

코어 검사에는 제작 및 선로 샘플링 루프 관리 할당 0, 시계 관찰자 분리, 경계 이벤트 순서, 상태 복원, 선로 중복 점과 양끝 처리가 포함돼. 실제 Unity 임포트/Burst, SaveSlot2 로딩·저장 시간, 전체 월드 무표시 결과는 검증하지 않았어.

## 다음에 필요한 이전

1. 남은 1·2단계 공통 IO/연결 복원을 먼저 이어서 실제 재고·유체·에너지의 데이터 접근 경계를 만들어야 해.
2. 생산·채굴·보일러·발전기 등 파생 설비의 상태와 입력/배출·자원 조회를 이 경계로 옮기고, 전력망 연결을 데이터로 등록해야 해.
3. 선로 ID/경로·점유·차량 연결·화물과 급수관 도킹을 이전하고, 수동 입력도 Tick 명령으로 받아야 해.
4. 개별 동물, 자원 성장·고갈, 농지·비료·파종 상태를 View 수명과 분리해야 해.
5. 일반 공장 및 전체 월드의 전체/일부/무표시 결과 비교를 통과한 뒤에만 3·4단계 완료와 5단계 근거리 View 로드를 적용할 수 있어.
