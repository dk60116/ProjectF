# Slot2 저장·로드 Initialize 병목 분석

## 결론

Slot2의 수분 단위 지연은 파일 읽기나 GZip이 아니라 누적된 3,357개 청크를 전부 다시 초기화하는 흐름이 원인임.

`RefreshChunks`는 플레이어 주변 청크를 추가하지만 반경 밖 청크를 해제하지 않음. 탐험한 청크가 `loadedChunks`에 계속 누적되고, 저장 시 `activeChunkCoordinates`에 전부 기록됨. 다음 로드에서는 `QueueSavedActiveChunks`가 이 목록 전체를 다시 생성 큐에 넣음.

`TerrainChunkStreamingScheduler`는 청크 하나가 끝날 때마다 다음 프레임까지 반드시 대기함. Slot2는 이 대기만 계산해도 다음 하한이 생김.

- 60 FPS: 약 56초
- 30 FPS: 약 112초
- 20 FPS: 약 168초

표면 생성 Job 대기, 설치물 복원, 리소스 등록, 후처리는 이 시간에 추가됨.

## Slot2 실측

파일: `slot_02.pfsave`

- 압축 크기: 950,904바이트
- 비압축 크기: 9,456,958바이트
- 단순 GZip 해제: 17ms
- 프로덕션 직렬화기 읽기·파싱: 0.36~0.54초
- 메모리 재직렬화·압축: 약 0.33~0.37초
- 활성 청크: 3,357개
- 리소스: 45,272개
- 설치물: 11,320개
- 컨베이어 설치물: 7,352개
- 컨베이어 상태 블록: 7,028개
- 컨베이어 레인 상태: 14,208개

Player 위치는 `(37.10, 0.00, 41.64)`이고 GameScene 설정은 `chunkSize=8`, `loadRadius=8`임. 시각적으로 물질화할 반경 내 후보는 다음과 같음.

| 항목 | 전체 | 플레이어 반경 | 감소율 |
|---|---:|---:|---:|
| 청크 | 3,357 | 289 | 91.4% |
| 리소스 | 45,272 | 3,934 | 91.3% |
| 설치물 | 11,320 | 1,424 | 87.4% |
| 컨베이어 상태 블록 | 7,028 | 907 | 87.1% |

시각 청크 수를 반경으로 제한할 수 있는 구조가 완성되면 리소스 컬렉션 선할당 상한도 약 221,184개에서 24,576개로 줄일 수 있음. 다만 현재 코드에서 큐만 289개로 제한하면 원거리 공정 시뮬레이션도 함께 빠지므로 그대로 적용하면 안 됨.

설치물의 점유 좌표를 청크로 환산하면 905개 청크에 공장이 존재함. 플레이어 반경과 설치물 청크를 합치면 1,091개이고, 나머지 2,266개는 적어도 `현재 시야`와 `설치물 점유` 기준에는 들지 않음. 이 2,266개는 탐험 이력만 남은 청크를 제거할 수 있는 큰 후보지만, 원거리 농지·동물·기타 의존 상태를 추가 검사한 뒤 제외해야 함.

최근 Player 로그에는 Slot2가 로드된 상태에서 씬을 교체할 때 `UnloadTime: 34572.500700 ms`가 기록됨. 대량 생성된 컴포넌트와 씬 오브젝트를 파괴·정리하는 비용도 별도 병목임.

## 원인 경로

1. `RefreshChunks`가 반경 밖 청크를 내리지 않음
2. `CaptureTerrainSaveState`가 누적된 모든 `loadedChunks`를 저장함
3. `LoadFromSaveState`가 저장된 모든 활성 청크를 큐에 넣음
4. 스케줄러는 한 번에 청크 하나만 처리함
5. 각 청크 완료 후 무조건 한 프레임을 대기함
6. 모든 청크가 끝날 때까지 `TryFinalizePendingWorldLoad`가 월드를 준비 완료로 만들지 않음

## 정확성 제약: 일부 청크만 로드하면 안 되는 이유

현재의 `청크 활성 상태`는 시각 표시만 뜻하지 않음. 공정 시뮬레이션에 필요한 런타임 객체와 연결 정보도 청크 복원 과정에서 만들어짐.

- 컨베이어·파이프·로봇팔은 데이터 전용 월드가 이미 있지만, 저장 상태가 해당 월드에 등록되는 시점은 현재 청크 복원 경로임
- 컨베이어 Job 토폴로지는 `ConveyorRuntimeRecord`만으로 구성되지 않고 로드된 `Block`과 레인을 노드로 사용함
- 생산기·채굴기·보일러 등 `InputOutputModule` 계열은 `MonoBehaviour`, `transform`, 로드된 Block을 사용하는 GameObject 기반 틱임
- `VirtualObjectWorld`는 현재 영속 ID와 거주 상태 레지스트리에 가깝고 전체 생산 공정을 대신 틱하지 않음

따라서 `QueueSavedActiveChunks` 입력만 플레이어 반경으로 자르는 변경은 큰 공장의 원거리 컨베이어와 생산기를 멈출 수 있음. 올바른 목표는 일부 **공정**만 로드하는 게 아니라 전체 공정의 **시뮬레이션 상태**를 등록한 뒤 근거리 **표현 객체**만 물질화하는 것임.

## 권장 변경 순서

### 1. 시뮬레이션 등록과 시각 청크 물질화 분리

로드를 다음 두 단계로 분리해야 함.

1. 전체 저장 데이터를 읽고 모든 공정의 상태·연결·인벤토리를 시뮬레이션 계층에 등록함
2. 플레이어 `loadRadius` 안에서만 지형 메시, 리소스 표시, Block 프록시, 설치물 렌더러를 물질화함

컨베이어·파이프·로봇팔은 기존 데이터 전용 월드를 확장해 전체 저장 상태를 청크 생성 전에 일괄 등록할 수 있음. 단, 컨베이어 Job이 `Block` 노드에 의존하는 부분은 좌표·레코드 기반 노드로 분리해야 함.

생산기·채굴기·보일러처럼 GameObject 기반인 설비는 먼저 원거리에서도 최소 GameObject만 유지하고 렌더러·콜라이더·시각 Block을 만들지 않는 과도기 방식을 쓸 수 있음. 이후 `FactorySimulationWorld` 같은 데이터 전용 틱으로 이전하는 게 최종 구조임.

이 분리 전에는 저장된 활성 청크 목록을 임의로 줄이지 않아야 함.

구조 분리 전의 과도기안으로는 `플레이어 반경 ∪ 모든 설치물 점유 청크 ∪ 공정 의존 청크`만 기존 방식으로 복원할 수 있음. Slot2의 기본 후보는 1,091개라 3,357개보다는 크게 작지만, 대형 공장 전체가 여전히 정상 틱되도록 농지·동물·자원·청크 경계 연결을 포함한 의존 집합을 먼저 정의해야 함.

### 2. 시각 청크 언로드 추가

플레이어 이동 시 반경 밖 청크를 다음 순서로 가상화하고 해제해야 함.

1. 청크 리소스·바닥 아이템·설치물의 최신 상태를 시뮬레이션 저장소에 반영함
2. 공정 틱과 연결 토폴로지는 계속 유지함
3. 렌더러, 콜라이더, Block 런타임 프록시와 표면 메시만 해제함
4. 시각 청크 인덱스에서 제거함
5. 다시 접근할 때 시뮬레이션 상태에 표현 객체를 결합함

이 작업이 없으면 장시간 탐험 후 동일 문제가 다시 누적됨.

### 3. 로딩 전용 청크 배치 처리

현재의 청크당 무조건 한 프레임 대기를 없애고, 로딩 화면에서는 총 시간 예산 안에서 여러 가벼운 청크를 연속 처리해야 함. 무제한 동기 처리가 아니라 프레임 시간 예산형 배치가 적합함.

### 4. 가까운 시각 청크 우선순위 적용

저장 목록은 y/x 순서이므로 플레이어 위치와 무관함. 표현 객체 생성 큐를 플레이어 청크 거리순으로 정렬해야 함. 월드 준비 완료 전에는 전체 공정 상태 등록과 최소 시뮬레이션 토폴로지 복원이 끝나야 하고, 모든 원거리 시각 청크 생성까지 기다릴 필요는 없음.

### 5. 저장 캡처 전역 검색 제거

`SaveActiveRuntimeInstallations`의 `FindObjectsOfType<InstallationObject>`를 영속 설치물 레지스트리 순회로 교체해야 함. 반경 밖 언로드가 적용되면 대상 수도 자연스럽게 감소함.

### 6. 리소스 저장을 변경분 중심으로 축소

절차 생성 기본값과 동일한 리소스는 저장하지 않고 채굴량·성장·제거 상태가 변경된 좌표만 저장하는 방식을 검토할 수 있음. 현재 Slot2 리소스 45,272개 전체 직렬화를 크게 줄일 수 있지만 포맷 의미 변경이라 초기 청크 제한 이후 진행하는 게 안전함.

## 검증 우선순위

- 반경 밖 설치물과 리소스가 저장 후 재방문 시 동일하게 복원되는지 확인함
- 청크 경계를 넘는 컨베이어·파이프·철도·전봇대 연결을 확인함
- 청크 언로드 직전 이동 중인 아이템과 로봇팔 상태를 확인함
- Slot2 초기 준비 시간과 씬 교체 `UnloadTime`을 다시 측정함
- 월드 전체 아이템 수 및 설치물 수가 저장 전후 동일한지 하네스로 확인함
