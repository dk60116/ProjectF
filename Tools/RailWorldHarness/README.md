# RailWorld Harness

철도·역 ECS 전환 1~5단계의 실제 데이터 월드와 경로 코드를 검사해. Unity 에디터나 게임을 실행하지 않아.

```powershell
& ./Tools/RailWorldHarness/Run.ps1
```

- `RailWorld`, `RailPathData`, `RailConnectionUtility`, `RailPathSampling`은 실제 소스 전체를 사용해.
- 철도 경로 생성·거리 샘플링과 자동운전 경로 플래너는 실제 메서드를 추출해. 역 이름·색 변경과 등록·해제는 실제 `Trainstation` 소스 전체를 사용해.
- 씬 객체 수명, 아이템 정의, 저장 DTO와 Terrain 연결은 대역이야. 실제 GameObject·Mesh·저장 파일을 만들지 않아.
- 원본 경로, 셀 끝점 확장, 좌표 기반 곡선, 최근접 위치와 길이를 검사해.
- 저장·표시 표현의 중복 제거, 청크 해제·재결합, 저장 경로 변경, 실제 철거, 무효 경로와 월드 초기화를 검사해.
- 고정 시드 무작위 철도망에서 연결 요소를 기존 전체 쌍 비교 결과와 대조해. 실제 자동운전 연결 판정의 모든 유효 쌍이 공간 검색 후보에 포함되는지도 검사해.
- 새 그래프의 경로 결과를 기존 전체 쌍 비교 그래프와 대조하고, 역 개명·색 변경·해제의 캐시 무효화를 검사해.
- 10,000개 희소 철도의 정확한 연결 검사 수와 워밍업 후 10,000회 조회의 관리 할당을 측정해. 긴 대각선은 공간 인덱스 크기가 사각 면적이 아닌 경로 길이에 비례하는지 검사해.
- Unity 프로젝트와 같은 C# 9로 컴파일해서, 새 컴파일러의 메서드 그룹 캐싱에 의존하지 않고 조회 할당을 확인해.
- 역 노선 조회·자동운전·디버그 표시의 씬 전체 철도·역 검색 제거를 소스 계약으로 확인해.
- 핸드카 프리팹이 참조하는 원본 ItemDefinition에 Boarding·Alighting 아이콘이 순서대로 연결되어 있고, GUID가 유효한 Sprite 에셋을 가리키는지 검사해. 아이템 파일명은 실제 이름과 다를 수 있어.
- `RailLineDebugRenderer`의 표시 전환, 재구축, 선로 수집, 선·방향 화살표 좌표 적용은 실제 메서드를 추출해. 네이티브 View가 없는 ECS 선로, 혼합 선로, 연결 색상, 높이, 표시 재전환, 철거와 월드 초기화를 검사해. LineRenderer·GPU·씬 수명과 열차 노선 마커는 대역이야.
- 표시 방향 연결 코드는 실제 partial 소스 전체를 사용해. 역방향 설치 조합, U자 곡선, 직각·스냅 연결, 단일·분할 순환선, 중간 분기와 철거를 검사해. 설치 순서와 무관하게 화살표 위치·방향이 유지되고 원본 경로는 변경되지 않는지 확인해.
- 시작점·끝점이 같은 부분 겹침, 완전 겹침과 곡선 끝부분 겹침의 역방향 설치 조합도 검사해. 같은 끝점을 공유한다는 이유만으로 화살표를 뒤집으면 안 돼.

`RailwayTargets`와 `RailWorld.Runtime`도 실제 소스 전체를 사용해. 컴포넌트 없는 철도·역의 연결, 자동운전, 좌표 검색, 개명, 색상 저장 상태와 지도 무효화, 철거, 같은 ID 재사용 시 오래된 타깃 무효화, 월드 초기화를 검사해. 데이터 좌표 검색 10,000회 관리 할당도 측정해.

열차는 `IRailTarget`과 `ITrainStationTarget`을 참조하고, 설치·복원은 데이터 타깃과 공유 렌더링 호스트를 사용해. 프리팹은 제작·미리보기 설정으로 남으며 편집 중에만 임시 컴포넌트로 전환해. 실제 메시·GPU 화면, 콜라이더, 청크 스트리밍 순서와 저장 슬롯 왕복은 게임 내 검증이 필요해.

공간 인덱스는 변경된 철도만 갱신해. 연결 요소 캐시는 변경 후 첫 조회에서 다시 계산하고, 자동운전의 노드 병합과 경로 탐색 알고리즘은 기존 방식을 유지해. 희소 철도 측정은 전체 게임 FPS나 밀집 분기망의 상한을 보장하지 않아.
