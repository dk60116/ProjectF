# ProjectF Benchmark Tool

EditorTool과 같은 로컬 TCP 수신기(`127.0.0.1:50877`)를 사용하는 별도 Windows 도구야. Unity 게임 코드에 Benchmark 기능이 포함된 상태에서 연결해. 게임 빌드 시 `Tools/BenchmarkTool` 폴더에도 함께 배포돼.

## 사용 순서

1. `새 Seed 0 맵 불러오기`로 현재 맵을 새 빈 흙 맵으로 교체해. 물·자원·나무·동물 없이 크기 제한을 무시하고 청크를 생성해.
2. 벨트 종류와 N줄을 선택하고 `N줄 생성`을 눌러. 기존 벨트와 그 위의 아이템을 모두 지운 뒤 플레이어 중심으로 반경 1, 2, 3…칸의 사각 순환 벨트를 붙여서 만들어. 맵을 다시 로드하지 않고 다른 설치물과 바닥 아이템을 유지해.
3. 아이템과 비율을 선택하고 `전체 벨트 채우기`를 눌러. `랜덤 아이템으로 채우기`는 같은 비율로 운반 가능한 모든 아이템을 섞어 넣어. 검색어는 랜덤 대상에 영향을 주지 않아. 유체·전기와 운반용 모델이 없는 아이템은 제외해. 기존 벨트 아이템을 지우고 양쪽 레인의 전체 슬롯을 기준으로 채워. 채우는 동안 시뮬레이션을 잠시 멈췄다가 이전 일시정지 상태로 복원해. `벨트 아이템 전체 제거`도 제공해.
4. 맵 오브젝트와 N개를 선택하고 `강제 소환`을 눌러. 플레이어 북쪽에 격자를 만들고 설치물 크기와 IO 영역을 고려해 간격을 둬. 지형·자원 설치 조건과 인벤토리는 무시해. 기존 설치물과 겹치면 오류 위치를 표시하고 중단해.
5. `모든 맵 오브젝트 클리어`는 설치물·벨트·아이템·저장된 오브젝트 상태를 비워. 플레이어 인벤토리는 유지돼.
6. 강제 작동 토글로 작동형 설치물에 전력·재료·자원·목표가 있다고 가정해. 일반 제작 시간과 작동 애니메이션을 사용해. 설정된 생산 결과는 실제 배출구 또는 바닥으로 나와. 채굴기·벌목기·로봇암의 가상 재료는 선택한 아이템이야. 정유기는 모든 출력 유체를 생성하고, 발전기는 발전 상태를 활성화해. 운송 펌프·살수기·파종기는 작업 상태와 시각 효과를 유지하되 임의의 생산 아이템을 만들지는 않아.
7. 상단에서 FPS, 시뮬레이션 UPS, 설치물 수, 벨트 아이템 수를 확인해. 아래에는 작업 단계·진행률·경과 시간·생성 아이템 수·유체 넘침량을 표시해.

## 수량과 실행 방식

총 벨트 수는 `4 × N × (N + 1)`이야. N=10은 440개, N=100은 40,400개, N=1,000은 4,004,000개야. 입력 즉시 생성 수량과 바깥 변 크기를 미리 보여줘.

생성 작업은 여러 프레임에 나눠 처리해. `생성 중단`을 누르면 이미 만든 오브젝트는 남아. 대기 중인 지형 청크 묶음은 생성을 마칠 수 있어. 벨트 생성은 누를 때마다 교체하고, 격자 소환은 기존 오브젝트를 유지하므로 겹치면 클리어하거나 플레이어 위치를 옮겨.

Seed 0 지형은 청크마다 흙 평면 한 장(정점 4개·삼각형 2개)을 만들고, 일반 지형의 바이옴 경계 계산과 비동기 메시 작업을 생략해. 기존 흙 높이·텍스처 좌표·블렌드 채널을 유지해. 격자 소환은 8행씩 지형을 준비한 뒤 바로 배치하므로 전체 지형이 준비될 때까지 기다리지 않아. 생성 목표 수는 시작할 때부터 표시하고, 지형 준비 중에는 완료 청크 수를, 일반 설치물 렌더 준비 중에는 처리한 레코드 수를 함께 표시해. 처리량이 정해지지 않은 준비 단계는 움직이는 진행 막대로 작동 중임을 표시해.

아이템 목록은 게임의 ItemDefinition에서 받아와. 초기 연결 실패·빈 목록·목록 요청 오류가 있으면 상태 조회 때 자동으로 재시도하고, 재연결이나 Host/Port 변경 시 새로 받아. 목록 아래에 검색 결과와 전체 벨트 아이템 종류 수를 표시해. 드롭다운은 배경과 글자 색을 명시해 다크 테마에서도 이름이 보이게 해.

사각 벨트는 방향별 템플릿 최대 8개를 만든 뒤 저장·시뮬레이션 데이터를 직접 등록해. 벨트마다 GameObject를 만들고 파괴하지 않아. 삭제·등록은 약 10ms 작업 예산으로 나누고, 지형 청크 생성 예산도 작업 중 10ms로 올려. 64개마다 시간을 확인하므로 한 묶음 비용에 따라 예산을 조금 넘을 수 있어. 생성 중 시뮬레이션과 벨트 렌더 갱신을 보류하고 완료·중단·실패 시 이전 상태로 복원해. 렌더 배치는 작업이 끝나면 재구성하므로 생성된 벨트는 그때 보여. 기존 벨트 삭제 중 중단하면 데이터와 블록의 일관성을 위해 삭제를 마친 뒤 멈춰.

격자 소환도 약 10ms 작업 예산을 사용하고, 오브젝트 하나를 등록할 때마다 시간을 확인해. 종류별 점유 영역과 배치 위치를 한 번 계산해서 재사용해. 벨트·파이프·로봇암·Building 계열은 템플릿용 오브젝트 한 개를 거쳐 데이터를 직접 등록해. 제작기·용광로·채굴기·정유기 같은 일반 작동형 설치물은 실제 인스턴스를 만들고 기존 IO 영역 초기화를 수행해. 철도·열차는 위치에 따른 설치 계산을 유지해. 생성 중 시뮬레이션, 파이프·로봇암·Building·정적 설치물의 렌더 갱신과 유체 연결 변경 알림을 보류해. 배치 후 일반 설치물·벨트·파이프의 렌더 레코드를 약 10ms씩 나눠 준비한 뒤 생성 작업을 완료해. 중단된 렌더 데이터는 다음 갱신에서 다시 구성해. 전력 연결망은 기존 일괄 갱신 API로 생성 중 재계산을 막고, 종료 후 필요할 때 갱신해. 개별 인스턴스 초기화, 충돌 메시 생성과 GPU 데이터 업로드 같은 단일 작업은 10ms를 넘을 수 있어.

변경 기능은 Seed 0 맵에서만 허용해. 강제 작동 상태는 세이브에 저장하지 않고 맵 로드·생성 시 해제해. 토글 전환 시 진행 중인 제작 작업은 초기화돼. 강제 작동 중 연결된 저장소가 받지 못하는 유체는 넘침으로 집계해. 이 모드는 입력 탐색·재료 수집·배출 대기를 생략한 부하 측정 모드라서 실제 공장의 전체 처리 비용과는 차이가 있어.

## 빌드와 검증

```powershell
dotnet publish Tools/BenchmarkTool/BenchmarkTool.csproj -c Release -o Tools/BenchmarkTool/publish
pwsh -File Tools/BenchmarkTool/RunChecks.ps1
pwsh -File Tools/BenchmarkTool/RunBulkChecks.ps1
pwsh -File Tools/BenchmarkTool/RunItemChecks.ps1
pwsh -File Tools/BenchmarkTool/RunPreparationChecks.ps1
pwsh -File Tools/CraftingTreeQuantityHarness/Compile.ps1
```

실행 파일은 `Tools/BenchmarkTool/publish/BenchmarkTool.exe`에 생성돼. `RunChecks.ps1`은 실제 BenchmarkLayout·BenchmarkCommand·강제 작동 어댑터·ProductionProcess 소스를 사용해 사각 루프의 연결 방향·수량, 비율 채우기, 명령 유효성, 제작 시간, 배출과 정유기 출력량을 검사해. 장면 IO와 시각 효과는 경계 대역으로 검사하며 Unity나 툴 화면은 실행하지 않아.

`RunBulkChecks.ps1`은 실제 TerrainGenerator 대량 등록 경로와 BlockStateStore 삭제 코루틴을 컴파일해 N=100 등록, 재생성, 파이프·기타 설치물 보존, 삭제 도중 중단과 실패 시 복원을 검사해. 격자 소환은 파이프·로봇암·Building·일반 설치물 각각 1,000개를 대상으로 본체와 IO 영역 구분, 저장 좌표 이동, 초기화 실패 시 정리와 렌더 갱신 보류를 검사해. 유체 알림은 실제 배치 처리 소스로 전체 모듈 깨우기·변경 알림의 일괄 처리와 일반 설치 흐름 복원을 검사해. 엔진 경계는 대역으로 처리하므로 실제 Unity 생성 시간이나 최종 렌더 재구성 비용을 측정한 결과는 아니야.

`RunItemChecks.ps1`은 실제 프런트엔드 목록 조회·검색·재연결 로직과 게임의 벨트 채우기 분기를 사용해. 빈 목록과 오류 후 자동 재시도, 이름 표시, 랜덤 대상 필터, 비율별 정확한 슬롯 수, 기존 아이템 교체, 실패·취소 시 시뮬레이션 복원을 검사해. 화면과 게임은 실행하지 않아.

`RunBulkChecks.ps1`에는 실제 수신기의 격자 생성 분기로 10만 개를 배치하는 검사도 포함돼. 전체 지형 준비 전 배치 시작, 행 묶음 경계의 정확한 수량, 취소 시 복원을 확인해. `RunPreparationChecks.ps1`은 실제 Seed 0 평면 생성과 렌더 준비 코드를 사용해 메시의 높이·방향·UV·색, 일반 설치물·파이프 10만 레코드의 분할 처리 및 중단 후 재구성을 검사해. 엔진·렌더 호스트·시간 측정 경계는 대역을 사용하므로 실제 게임 성능 측정값은 아니야.
