# 분배벨트 검사

엔진을 실행하지 않고 실제 `SplitterRoutingPolicy`, `Block.Splitter`,
`Spliterbelt.Routing` 코드를 관리형 월드 대역과 연결한다.

```powershell
dotnet run --project Tools/SplitterHarness/SplitterHarness.csproj '-p:UnityManagedDirectory=C:/Program Files/Unity/Hub/Editor/6000.4.0f1/Editor/Data/Managed/UnityEngine'
```

4,850개 단언은 두 입력의 공정한 교대/좌우 교차, 단일 입력의 교대 출력,
한쪽 출구 막힘 우회, 양쪽 막힘 시 보존, 아이템 회수 후 양쪽 입력 깨우기,
필터의 엄격한 출력 분리, 투입 애니메이션 완료 대기, 동일 프레임 중복 이동 방지,
필터/교대 상태 복원 및 풀 재사용 초기화를 확인한다.

바퀴 상태 검사는 네 방향에서 직진/교차 확정 결과와 표시 지연을 확인한다.
빈 대기줄, 이동 시도 실패, 필터와 우회 출력, 양쪽 독립 타이밍, 연속된 같은 결과,
지연 중 반대 결과, 저장 상태 복원과 풀 초기화를 포함한다. 시간은 관리형 대역으로
주입하며 지연 판정은 실제 코드다. Transform 회전과 메쉬 방향은 화면 검증 대상이다.

블록 점유 조회와 슬롯·예약·프레임 상태는 대역이며, 전체 벨트 스케줄러와 실제 로봇팔,
프리팹 렌더링/충돌, Unity UI는 실행하지 않는다. 네 회전의 입력/출력 연결,
로봇팔을 이용한 두 칸의 투입·회수, 막힘 해제 및 필터 UI는 게임에서 추가 확인한다.

기본 동작은 입력을 번갈아 선택하고 출력을 번갈아 선택한다. 양쪽 입력이 계속 준비되면
왼쪽 입력은 오른쪽 출력, 오른쪽 입력은 왼쪽 출력으로 교차한다. 한쪽만 입력되면
그 입력이 두 출력을 번갈아 이용한다. 선택한 입력/출력은 실제 이동을 적용할 때만 갱신한다.

필터 UI는 `FILTER OFF`, `FILTER LEFT`, `FILTER RIGHT`를 제공한다.
필터 켜짐 상태에서 선택한 아이템은 지정 출력으로만, 나머지는 반대 출력으로만 간다.
지정 출력이 막힌 필터 아이템은 대기하며 반대편의 허용 아이템은 계속 처리한다.
커스텀 속도는 프리팹 `Conveyor Speed`에 지정한다(초깃값 0.5).

분배기 본체와 바퀴는 네이티브 렌더러를 유지하고 루트를 비활성화하지 않는다.
따라서 본체 충돌, 필터 포커스, 바퀴 회전이 가상 벨트 렌더링 상태와 무관하게 유지된다.
각 바퀴는 실제 위치의 벨트칸에 연결하며, 분배기 기준 Y축으로 회전한다.
각 칸에서 직진 통과를 확정하면 해당 Wheel이 회전하고, 옆으로 보내기를 확정하면
멈춘다. 표시 전환은 기본 0.15초 뒤이며 Inspector의 Wheel Transition Delay로 조절한다.
다음 확정 결과가 나올 때까지 아이템 유무와 무관하게 그 상태를 유지한다.
표시 지연 중 저장할 때는 최종 목표 상태를 저장하며 복원 시 해당 상태로 바로 표시한다.
이동 애니메이션은 Wheel을 다시 켜지 않는다. 최초 설치 및 풀 재사용 시 두 Wheel 모두 정지한다.
버전 52 저장은 필터 출력, 다음 입력/출력과 각 Wheel의 회전 상태를 보존한다.
아이템 ID 마스크 및 슬롯 아이템 저장은 기존 체계를 재사용한다.
