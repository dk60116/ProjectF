# 로봇팔 생성·틱 최적화 회귀 검사

`./Tools/RobotArmOptimizationHarness/Run.ps1`로 실행해.

실제 캐시 조회, 전력 요구량, 저장 DTO 작성, 틱 계측 집계, 공간 인덱스 선택, 근처 콜라이더 풀링 메서드를 추출해 검사해. Unity 엔진은 실행하지 않고 네이티브 컴포넌트·프리팹 캡처 경계는 관리 코드 대역을 사용해.

- 같은 원본과 아이템 ID의 10만 번 등록에서 템플릿을 공유하고, 서로 다른 아이템 ID는 구분해.
- 100만 번 전력 조회에서 정의를 다시 찾지 않고, 10만 번 저장 갱신에서 DTO를 할당하지 않아.
- 상세 계측은 틱마다 256개 중 하나의 팔을 돌아가며 측정해. 10만 팔에서 단계당 390~391개만 시간 조회를 하고, 256틱 동안 모든 순번이 한 번씩 측정되는지 검사해. 비활성 계측은 시간 조회와 할당을 하지 않아.
- Pickup/Drop Query도 같은 표본에 포함해. 표본 밖의 팔은 조회 시간을 재지 않고, 틱별 합계만 프로파일러에 기록해.
- 대기 상태와 수면 가능 상태 확인은 실행당 상태 슬롯을 한 번만 조회해. 10만 대기 실행의 조회 횟수와 무할당을 검사하고, 아이템 유무·타이머 경계·음수/0/부분/큰 시간값에서 명령과 상태 전환이 유지되는지 대조해.
- 입력·출력 회전은 전력 25%·50%·100%에서 기존 완료 틱을 유지해. 회전 중 아이템이 제거된 경우와 도착 후 재시도 타이머도 검사해.
- 회전 완료 틱과 표시 자세를 기존 RotateTowards 방식과 대조해. 540도/초 반회전의 20틱 동안 각도 계산은 한 번이고, 화면에 보이지 않는 팔은 보간하지 않아. 방향 반전·무전력·저장 중간 자세도 검사해.
- 항상 전력이 공급되는 틱의 10만 조회는 전력 소비 함수를 호출하지 않아. 실제 전력망의 부분 공급과 무전력 수면은 유지해.
- 손 위치의 원본 월드 행렬 결과와 새 로컬 자세 캐시를 비균일 원본 스케일·설치 회전·두 애니메이션에서 대조해. 같은 자세의 10만 팔은 행렬 계산을 공유하고 월드 위치는 구분해.
- 저장된 입력 후보는 현재 조회의 손 위치를 전달받고, 저장된 컨베이어 제거는 선택 당시 몸 위치를 재사용해. 출력 기준점과 이송 시작점도 같은 손 위치를 사용해. 중복 위치 헬퍼와 전수 Query 계측이 남지 않았는지 배선 검사해.
- 플레이어 이동·편집·제거 시 충돌 컴포넌트 소유권과 풀 재사용을 검사해.
- 네이티브 콜라이더가 없는 먼 로봇팔도 원본 구체 모양으로 선택해. 음수 좌표, 셀 경계와 긴 광선의 순회도 검사해.

실제 물리 충돌과 FPS/생성 시간 개선 폭은 Unity 플레이어에서 별도로 측정해야 해. `RobotArmWorld.ActiveColliders`, `PooledColliders`, `LastApplyCommands`, `DetailedTimingStride`로 새 경로를 확인할 수 있어. 전체 비용 비교는 `Robot Arm Entity Plan/Apply`를 사용해. `(sampled)`가 붙은 전력·상태·수면·이송·Query 행은 선택된 팔/명령의 틱별 합계이고 전체 비용으로 환산하지 않아. 기존 전수 Query 행과 새 표본 Query 행의 시간 수치를 직접 비교하지 않아.

`RobotArmEcsHarness`는 10만 활성 팔 중 준비된 두 팔만 Apply하는지, 같은 슬롯의 경합 순서·중복 Apply·Plan 이후 제거와 저장 횟수를 검사해. 활성 팔의 Plan 주기 자체는 60Hz를 유지해.
