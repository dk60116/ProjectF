# 컨베이어 경로·상판 UV·플레이어 측면 충돌 검사

Unity를 실행하지 않고 실제 런타임의 경로·이동 시간·상판 UV 헬퍼와 Unity의 관리형 벡터 연산을 사용한다.
.NET 9 SDK와 프로젝트가 사용하는 Unity의 `UnityEngine.CoreModule.dll`이 필요하다.

```powershell
dotnet run --project Tools/ConveyorPathHarness/ConveyorPathHarness.csproj '-p:UnityManagedDirectory=C:/Program Files/Unity/Hub/Editor/6000.4.0f1/Editor/Data/Managed/UnityEngine'
```

설치 위치가 다르면 `UnityManagedDirectory`를 변경한다.

- 네 방향 × 양쪽 합류 × 시작 위치 오프셋 3종: 총 24개 경로
- 합류 전 옆밀림 없음, 합류 후 중심선 유지, 직각 회전, 역방향 이동 없음, 실제 이동 거리
- 직선/맞은편/동일 블록/두 칸 이상 떨어진 연결을 측면 합류에서 제외
- 합류 직전 슬롯을 거치는 두 구간이 각각 기본 간격 길이인지 검사
- 세 가지 속도에서 압축 입력과 출구 막힘/해제 이후의 출발 간격을 슬롯 모델로 검사
- 1F → 2F의 다섯 상판 → 1F 연결에서 양 끝과 내부 경계의 텍스처 위상을 함께 검사
- 상판 검사는 네 방향, 정수/소수 월드 위치, 경사 높이 3종, 속도 3종, 시간 4종 및 Seam 확장을 포함
- 2F 측면 충돌 792개: 네 방향, 충돌 반경 3종, 양쪽 측면 진입·이탈, 빠른 이동,
  대각선 접촉과 옆면 따라 이동, 입·출구 통과, 설치 시 겹침 탈출,
  양 끝의 좁은 평지 측면 통과, 평지에서 중심선을 따라 올라가기 및 경사면 측면 차단

측면 검사는 실제 `ConveyorSideBarrier`의 연속 충돌 계산을 사용한다.
양 끝의 평지 메쉬 `Body_Start`/`Body_End`의 안쪽 경계 사이만 측면을 막는다.
플레이어 충돌 반경은 측면 간격에 적용하고 길이 방향 끝은 평지 경계에서 자른다.
따라서 좁은 평지에서도 옆으로 통과할 수 있으며 경사면과 높은 구간의 측면은 차단된다.
관리형 검사는 실제 설치/제거에 따른 점유 조회, Rigidbody 및 Physics와의 결합을 실행하지 않으므로
게임에서 2F 네 방향 설치와 제거, 상판 위 옆걸음, 장애물에 붙은 모서리 이동을 추가로 확인한다.

1F와 Seam은 수평 진행 좌표를 공유한다. 2F의 다섯 상판은 실제 표면 길이를 사용하며,
추가 경사 길이에 필요한 반복 수를 올림해 양 끝의 1F 위상을 유지한다. 따라서 2F 무늬는
1F보다 성기지 않고 다섯 상판에서 같은 표면 밀도를 갖는다. 정수 반복 보정으로 2F 전체가
1F보다 조금 촘촘해질 수 있다. `BeltTopUvChecks`는 런타임 UV 계산
헬퍼를 직접 사용하지만 실제 프리팹 배치나 GPU 셰이더 실행을 검증하지는 않는다.

이 검사는 슬롯 점유 경쟁, 막힘 해제, GPU 표시를 포함한 게임 플레이 검사가 아니다.
게임에서 T자 양쪽 합류, 본선과 동시 유입, 출구를 막았다가 해제하는 경우,
이동 중 아이템 선택/획득 및 2F 교차를 추가로 확인한다.

측면 입력 벨트는 기존 앞 슬롯과 수신 앞 슬롯 사이에 슬롯 1을 사용한다.
두 구간을 각각 기본 아이템 간격으로 나누어 긴 합류 경로 전체가 하나의 예약을
점유하며 처리량을 낮추지 않게 한다. 슬롯 1의 사용 여부는 일반 직선 묶음 처리,
전후 슬롯 탐색, 이동, 표시 경로에 함께 적용한다. 2F의 슬롯 1은 재사용하지 않는다.
수신 벨트에서는 중심에서 진행 방향으로 꺾여 앞 슬롯으로 이동한다.
뒤 슬롯을 목적지로 사용하면 합류 후 역주행이 생기므로 사용하지 않는다.
